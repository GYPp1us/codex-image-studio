codex-image-studio · 竖屏交互范式 · 提案 v0.3

One object per surface, one home per action

This proposal targets two structural problems: what an image tap means (C), and Queue and Works showing the same thing (D). The phone on the right is a working prototype that runs on simulated data and doesn't call the backend. Tasks progress on their own, so leave it running for a few seconds and the results will start arriving.

On the phone, drag a sheet's handle down to dismiss it. In the viewer, swipe left/right to change images, swipe down to close, and tap the image to hide the controls. Long-press (or right-click) a grid image to open its menu. The browser back button works as the system back.

1 · Object model

The current UI mixes four nouns on most screens. The new rule: each surface has exactly one primary object. Anything else on that surface is either a summary that links to the object's home, or it isn't shown.

Fixing D: Works shows results, Tasks shows the process.Works no longer renders a placeholder card per pending task. A list with work in flight shows one live strip (“3 张生成中 · 主模型正在思考”) that links to the batch in Tasks, and finished images drop into the grid with an enter animation. Tasks groups by batch_id (already stored on jobs), so the prompt appears once per submission rather than once per image. Cancel, retry and logs exist only in Tasks.
Fixing C: tapping an image opens the image.Today a tap opens a metadata edit form, “点击放大” is needed to see the image full-size, and local redraw is one level deeper again. Name, tags, the original prompt and the task record move into the ⓘ info sheet.

2 · Navigation and depth

  • Four tabs: 创作 · 作品 · 任务 · 模板. 参考图库 is no longer a tab. It becomes the picker sheet behind “+” in Create, which has 参考图 and 作品 tabs. Upload lives there too.
  • Avatar sheet: account, call settings, recently deleted, install app, sign out. The top-right “install” icon (which looked like a download button) is removed.
  • Depth: tab → list (push) → viewer (overlay) → sheet (overlay). Only one sheet is open at a time. A second step, such as 模板 ▾ → 保存为模板, replaces the sheet's content and animates its height instead of stacking another dialog.
  • Generating doesn't navigate. You stay in Create: the button changes to “已加入 3 张”, a dot flies to the 任务 tab, its badge bumps, and a batch pill above the button links to where the results will land.

4 · Visual hierarchy rules

  1. At most one filled dark button per surface. 生成 in Create, the primary action in a sheet. Download is not the primary action of an image.
  2. Cards show content, not controls. Grid tiles show only the image. List cards show cover, name and count. Actions are in the viewer, the long-press menu or ···.
  3. Destructive actions go last in menus, in red, and can be undone. Deleting already goes to 最近删除, so the toast offers 撤销 instead of a confirm dialog.
  4. Summarize state where the user is looking. Use one live strip or stage bar, never N placeholder cards.
  5. Show system status only on exceptions. The disconnected/paused banner appears only when it applies.
  6. Show filing before submit. “归入 · X” sits under the prompt. If the text has drifted far from the template, a warning offers 改为无模板.
  7. Use one control type per kind of input. Segmented options for enums, switches for booleans, a stepper for counts, no native <select> in sheets. Non-form sheets close by drag, scrim or ×, with no separate 完成.
  8. Hide the tab bar while typing. With the keyboard up, the tab bar slides away and the generate bar docks to the keyboard (try “输入态”).

6 · Back stack

Each overlay pushes one history entry: list, viewer, redraw mode and sheet. System back, browser back, the × button, a scrim tap and a drag-dismiss all go through history.back(), so they behave identically and close one level at a time. Tabs don't push entries. Tapping the active tab returns to its root or scrolls to the top. On Android, studioBack() becomes “if depth > 0 then history.back()”.

7 · Mapping to the current code

  • navigate() → wrap in document.startViewTransition and give #page a view-transition-name. Where unsupported, it falls back to an instant switch.
  • modal() (single shared <dialog>) → a sheet host with a history entry per layer, plus a content-swap helper for multi-step sheets.
  • StudioDOM.updateHTML is already a keyed morph. Add FLIP for moved keys and an enter class for new keys, which is what syncList() does in this demo.
  • viewer.js already handles pushState, pinch zoom and 100% view. Keep those, open it straight from tiles with the shared-element fly-in, and move the assetDetail form into an info sheet.
  • renderQueueItems → group by batch_id. renderRecent/assetCard → remove the action rows and add the long-press handler.
  • Status bar hints → removed. Connection and pause state become banners.

9 · v0.2 additions

These follow the same rules: one home per action, everything reversible, and the cost of an action shown before you commit to it.

Clear all (清空)

A small text button next to “模板 ▾”, shown only when there is something to clear. It clears the prompt, reference images and template binding but keeps the generation parameters. The toast offers 撤销 for 5 seconds, so there is no confirm dialog.

Quick edit (速改)

  • Its home is an input pill in the viewer, above the action bar. Focusing it hides the action bar and shows suggestion chips. Enter sends.
  • It reuses the original image's ratio and size, with the original as reference. The line under the input states exactly what will be sent (“按原图规格 · 16:9 · 1792×1008 · medium”), and tapping it opens the 速改 section of Settings.
  • It is also in the long-press menu as a small sheet, so you can quick-edit from the grid without opening the image.
  • Results get a “速改” badge, link back to their source in ⓘ, and (optionally) toast with “查看” when done.

Upscale failure and multi-tile redraw

  • This follows the new backend model: 4× / 16× / 64× area = 1 / 2 / 3 levels, and each level has parallel tiles followed by one review. Before submitting, the sheet lists each level's sizes, tile count and total calls.
  • Progress is shown as a tile map (one cell per tile) instead of stage bars, so you can see several tiles running in parallel.
  • On failure, the Works strip and the task both say “处理”. That opens a full-screen workspace with the three panes from upscale-failure.js (原图对照 / 直接拼接 / 仿射诊断), a tile overlay you tap to multi-select, quick selections (问题块 / 全选 / 清除), and per-tile 对比 (input ↔ output).
  • The submit bar states the cost (“3 次生图 + 1 次验收”). When the selection is larger than the concurrency limit, it says so and links to the setting. Leaving a problem tile unselected shows a warning, and the task then fails with the backend's own “仍未通过 … 请选择该块” message.
  • Selected tiles run in parallel through the shared session pool. Unselected tiles are reused.

Settings (设置)

A single page reached from the avatar sheet, replacing the separate 账户设置 / 调用设置 entries. Sections: 账户 · ChatGPT 订阅 · 生成默认值 · 速改 · 超分 · 任务队列 · 调用提示词 · 显示与存储. Changes save immediately (a small “已保存” appears in the header). Other surfaces deep-link to the relevant section and briefly highlight it: the viewer's spec line → 速改, the concurrency hint → 任务队列, “设为默认” in the params sheet → 生成默认值. The prompt editor validates {prompt} live and offers variable chips. Clearing the cache asks for a second tap instead of a dialog. 并发会话 and 动效 affect the demo immediately.

10 · v0.3 additions

Upscale has its own home

Create now has a 生成 / 超分 switch in its header. 超分 mode is a complete form, so you no longer need an empty prompt plus the stitch option:

  • 原图: a large picker with a row of recent works for one-tap selection. 选择/更换 opens the picker (作品 / 参考图库 / 从相册上传) in single-select mode, where tapping an image picks it and closes the sheet.
  • 面积倍率 4× / 16× / 64× with the per-level plan and call budget.
  • 统一细节与画风约束, prefilled from Settings.
  • The button reads 开始超分 and gives the same submit feedback as 生成.

The viewer and long-press 超分 entries remain as shortcuts. The old 超规格拼接 option in the parameters sheet becomes 生成后超分 (关 / 4× / 16× / 64×), which queues an upscale for each image as it finishes.

Progress that scales to any count

Each task card now shows one full-width segmented bar, with one segment per image, tile or region. Each segment fills by stage, shimmers while running, and turns red or amber on failure. The counts go on their own line (“2/4 完成 · 1 生成中 · 1 等待”), so 1, 4 or 20 images all fit at 360 px. The Works live strip and the batch pill use the same bar at a fixed width.

Multi-region local redraw in parallel

  • In redraw mode you can draw up to 6 rectangles. Tapping inside one selects it, dragging on empty space adds another, and × removes it. Overlapping rectangles are refused, because the merge couldn't decide which edit owns those pixels.
  • Each region has its own instruction, chosen with the #1 #2 chips. Alternatively, the “同一条要求” switch applies one instruction to all regions. The submit button names any region that still has no instruction.
  • Regions run in parallel through the shared session pool, then merge into one new image that replaces only pixels inside the selections. In Tasks, each region is a segment of the bar, and the expanded card lists each region's instruction and stage plus the merge step.
  • Backend change needed: POST /api/assets/{id}/inpaint takes regions[] (each with its own prompt), runs local_edit.prepare per region as child calls in CALL_POOL, then applies local_edit.compose for each region in turn onto the same base. Compose is already exactly bounded, so non-overlapping regions can't interfere.
